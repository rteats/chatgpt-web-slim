# ChatGPT Web Slim — Live Reader v0.2.7

Experimental independent Chromium-extension frontend for browsing ChatGPT history without loading the official website's JavaScript. The private backend is undocumented; compatibility and authorization are **not guaranteed**. Not affiliated with OpenAI.

## Install / update

1. Download the source ZIP from branch [spike/live-har-protocol](https://github.com/rteats/chatgpt-web-slim/tree/spike/live-har-protocol), extract it and select the **live/** folder in chrome://extensions → Developer Mode → Load unpacked.
2. If updating an unpacked extension, copy the new **live/** files and press **Reload** on chrome://extensions. Close the old Live Reader tab.
3. Sign in normally to https://chatgpt.com in the **same browser profile**, open a conversation, and wait until the site loads the sidebar.
4. Open the extension toolbar popup → **Открыть лёгкий клиент**.

The extension captures one workspace-routing header from first-party requests into session storage. It does not save cookies, access tokens, message bodies, or request/response content. Nothing is uploaded by the extension.

## New: opt-in network metadata analyzer (v0.2.6)

**Purpose:** When the ordinary ChatGPT UI displays conversation history, but the Web Slim reader receives HTTP 200 with zero items, compare the **actual request metadata** generated by the official app to that of the standalone extension. The old v0.2.5 "site" probe also used a *manual isolated-world fetch*, not the official JavaScript client's request.

### Collect a useful report

1. Keep an ordinary signed-in ChatGPT tab open.
2. In Web Slim, expand **Сетевой анализатор (метаданные запросов)**.
3. Select the ordinary ChatGPT tab from the dropdown. If multiple tabs are open, select the one you intend to use.
4. Click **Начать запись**.
5. Return to the selected ordinary ChatGPT tab. Reload it or switch between 2–3 conversations and wait for them to load.
6. Return to Web Slim, click **Подключиться / обновить список** once. This creates an *extension-origin* list request while the capture is active.
7. Click **Остановить**, then **Скачать отчёт**.
8. Send the resulting **web-slim-network-report.json** in private chat. Optionally attach the standard **web-slim-diagnostics.json** too.

This captures existing requests; it sends **no new traffic** itself. Both sides' requests are summarized by method, fixed endpoint category, allowlisted URL *parameter names*, allowlisted request *header names*, HTTP status, MIME category and duration.

### Scope and limits

- Capture is **off by default**, starts on explicit click, applies to the **chosen official browser tab** and requests originating from this extension, and is restricted to allowlisted chatgpt.com/backend-api/ endpoints. No URLs or path IDs are saved.
- Maximum **80 completed requests** or **three minutes**, whichever comes first. Stop and clear are explicit. No polling, proxying, modifying requests or replaying credentials.
- Data is stored only in **chrome.storage.session**, cleared on extension reload/browser restart; a download is created only on explicit user action. The selected tab ID is retained internally for filtering, **never exported**.
- Header *names* come from a static allowlist covering the supplied HAR. Unknown names are omitted. Values are never included. Cookie/Authorization **values** and message content never enter the report.
- Chrome's webRequest API may not expose some browser-generated headers. This is a diagnostic of Chrome's **visible metadata**, not a guaranteed packet-level/full-header capture.
- onCompleted has no response body; the analyzer **cannot count how many conversations the official app received**, just HTTP status and response type. Use the normal UI to verify messages appear.
- The original plugin inventory GET is unchanged; if the server responds HTTP 451, do not repeatedly retry or circumvent its refusal.

### Why JavaScript might matter

The official app can use an API client, service worker or fetch middleware to provide additional request headers and state. The warm-cache and sending HARs showed header names including **oai-device-id**, **oai-did**, **originator**, **oai-language** and **x-openai-web-frontend** in successful first-party conversation-list requests. Web Slim currently supplies Accept and ChatGPT-Account-ID, plus whatever the browser adds. Those differences are evidence for further investigation, **not** proof of why the API returned an empty list; avoid copying HAR-captured ID/token *values*.

## Current functionality / limits

Read-only history, conversation pagination, session-check button, plugin inventory attempt, and safe diagnostics. No live sending, actual plugin execution, file upload or standalone Plus subscription integration. The optional stream parser is offline-only.

## Source/privacy

Do **not** commit actual HARs, conversation exports, traces, cookies, authentication data or user messages to this public repository. Send only the sanitized metadata report, after reviewing it yourself. The official ChatGPT API and ChatGPT subscriptions are separate products; undocumented web APIs can change or restrict access without notice.

Chrome reference:
- https://developer.chrome.com/docs/extensions/reference/api/webRequest
- https://developer.chrome.com/docs/extensions/reference/api/storage

## v0.2.7 — avoid inconclusive reports

The first v0.2.6 report contained **three official-site requests** (two conversation details, one installed-plugin inventory) and **zero extension observations**. There was no official **conversations.list** call either. That is **not a pairwise comparison**, and the v0.2.6 presentation incorrectly made unpaired headers look like differences.

In v0.2.7, the analyzer:

- Labels unpaired routes as **incomparable**; does not manufacture missing-header differences.
- Independently instruments the Web Slim reader's list-request start, success and failure using an allowlisted message that contains **only operation, phase and HTTP status**. If Chrome does not expose extension-origin requests through webRequest, the report still records that the client attempted a GET.
- Shows a warning when there was no ordinary-site conversation-list request, no Web Slim attempt or no webRequest observation of Web Slim's request.
- Continues to collect header names passively, **never** authorization values, cookies, message content or IDs.

### Exact next experiment

1. Start monitoring the correct official ChatGPT tab.
2. **Reload that official tab** to cause a real, fresh conversation-list GET (opening already-cached chats alone may not cause one).
3. Return to Web Slim and click **Подключиться / обновить список** once **while monitoring is still active**.
4. Stop and download. Review the UI's coverage warnings; if official conversation-list was not observed, the comparison remains incomplete.

The observed official requests include an **Authorization** header name, while the extension api.mjs explicitly constructs only **Accept** and **ChatGPT-Account-ID**. This is a concrete architectural difference, but no token values have been captured and no credential replay or access-control bypass is implemented. The experiment must not be used to extract account credentials or circumvent API access policy.
